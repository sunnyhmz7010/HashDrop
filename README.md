## ✨ 为什么做这个项目

为单台 VPS 提供维护负担较小的数字商品商城。生产环境只有 Go 单体服务与 SQLite，收款和到账识别独立交给 HashPay。匿名买家无需账号，凭下单时设置的领取密钥查询订单和领取商品。

## 🚀 核心能力

- 商品卡片提供详情与下单两个图标入口，详情支持 Markdown、图片和视频；弹窗内设置领取密钥后直接跳转 HashPay，支持中英文与移动端。
- 商品与库存池独立管理；多个商品可共享同一池的卡密或账号库存，原子预留、防重复导入与重复交付。
- 固定文本使用购买时的加密快照，支付后直接领取，不消耗库存。
- 常驻或限时优惠活动与优惠码，支持单个、多个或全店商品，比例或固定金额减免、门槛、限次和双方叠加许可。
- 网页完成首次初始化；一位管理员管理商品、库存、订单补偿及站点和支付设置。
- 独立赞赏页支持预设与自定义金额，复用 HashPay 收款，后台管理页面设置、赞赏记录与按币种汇总的已核验收款。
- HashPay RSA 签名请求、加密回调和签名二次查询，付款与交付状态分别保存。
- 内置补查、交付恢复、在线备份校验，管理员 Argon2id 密码。

## ⚡ 快速开始

### 📋 前置要求

- 构建机：Go 1.27+、Node.js 24+、npm。
- 生产 VPS：Linux、Docker Engine、Docker Compose V2；无需 Go、Node.js、Redis 或 MySQL。
- 支付：可用的 HashPay 原生 REST API 商户与商户 RSA 私钥。

### 📦 安装与运行

v1.0.0 是全新安装基线。推荐使用 GitHub Actions 构建并发布的 GHCR 镜像，以及[对应的 Compose 文件](https://github.com/sunnyhmz7010/TinyFaka/blob/v1.0.0/compose.yaml)，默认固定镜像为 `ghcr.io/sunnyhmz7010/tinyfaka:1.0.0`。将 `compose.yaml` 保存到部署目录，然后执行：

```sh
docker compose pull
docker compose up -d
```

浏览器访问 `http://服务器地址:8080`，自动进入初始化页面，直接填写管理员账号和密码，无需初始化凭证。页面同时提供站点名称、地址和 HashPay 商户信息；商城公告在初始化后的后台系统设置中填写。密码不要求最小长度或字符组合，只须非空并与确认密码一致。配置与密钥由服务端生成并保存到 Docker 持久化卷；无需填写环境变量或手工编辑配置文件。HTTP 会明文传输密码与私钥，应在可信网络中完成初始化。

容器中 `/app/tinyfaka` 是程序，`/data` 统一保存配置、私钥、数据库和备份，Compose 只挂载一个数据卷。首次启动通过内嵌的 `schema.sql` 一次性创建完整数据库结构，后续启动直接打开已有数据库；v1.0.0 不提供早期实验版本的升级迁移。

Compose 默认镜像为 `ghcr.io/sunnyhmz7010/tinyfaka:1.0.0`，也可换成 `latest` 或镜像摘要。只有推送 `v*` 版本标签才会发布镜像，推送 `main` 不触发发布。更新执行 `docker compose pull` 和 `docker compose up -d`，已有初始化信息保留。

## 📖 使用说明

管理员使用初始化时设置的账号和密码登录。交付类型由库存池管理，支持卡密、账号和固定文本。

顶栏右侧可切换中文和 English，语言偏好保存在当前浏览器。商城与后台共用顶栏，点击站点品牌返回首页；商城根页面在语言选择右侧提供“管理后台”按钮，后台在同一位置提供“退出登录”按钮。

管理员入口 `/admin`。HashPay 可以在初始化时填写，也可以在后台系统设置补充或替换商户私钥，保存后不会回显。后台分为“商品管理”（`/admin/products`）与“库存管理”（`/admin/inventories`）：先独立创建库存池并选择交付类型，卡密或账号按行导入，固定文本填写交付内容；再创建商品、选择库存池并上架。未关联库存池的商品可保存为下架草稿。HTTP 站点通过签名查询补查付款，无需配置回调；HashPay 回调只接受 HTTPS 地址。使用 HTTPS 站点时，可在 HashPay 设置 `站点地址/api/webhooks/hashpay`。

一个商品关联一个库存池，同一库存池可被任意多个商品共享，商品的售价、币种和优惠规则仍各自独立。可用、预留、已售数量按库存池统计，共享商品显示同一份库存，总览不会重复累计。库存池可以先于商品创建，也可以在商品删除后继续使用；仅允许删除尚未预留的库存项。删除库存池前须解除全部商品关联，且不能有订单预留，历史记录保留。

编辑商品时可更换或解除库存池关联；上架商品须关联有效库存池。更换关联只影响新订单：既有订单保留原交付类型、库存来源及固定内容快照，继续从原库存履约，可靠终止时也向原池释放预留。库存池建立后不能改变交付类型，如需调整可创建新池再改绑商品。

已付款且交付完成、已关闭或已失效的历史订单不阻止更换 HashPay 地址或商户。待核验付款或尚未完成交付的订单仍保护原配置，即使已从后台删除也不例外。更换后原领取链接继续可用，旧订单的支付状态查询须使用原网关和商户配置。

首页商品卡片的眼睛图标打开详情，购物袋图标直接打开下单弹窗。详情页由顶部商品信息和下方详情内容两块组成，点击下单后再选择数量、确认金额。下单弹窗不显示库存数量，打开时仍重新读取商品价格与库存以限制购买数量，最终以服务端校验为准。

后台可为商品独立开启“隐藏商品”。已上架的隐藏商品不出现在首页及公开商品列表，只能通过详情链接访问和购买，详情页不显示返回商城按钮；下架商品仍无法查看或下单。后台点击已上架的商品名称即可打开详情链接。商品默认不隐藏，隐藏设置与上架状态分别保存。

后台支持删除商品。删除后从商城及后台商品列表移除，并停止新的下单；独立库存池、对应订单、库存预留、付款补查和领取结果保留，已创建的订单仍可完成付款与交付，其他共享商品继续使用原池。商品采用逻辑删除，避免破坏订单关联。

后台商品编辑将商品介绍和商品详情分别保存。介绍显示在首页卡片和商品页顶部：首页最多展示三行，商品页顶部展示完整介绍，两处共用标题、库存、价格的样式与排列。下方仅展示独立的 Markdown 详情，未填写详情时不显示该内容块。详情支持编辑与预览。图片写作 `![图片说明](https://example.com/image.jpg)`；视频直链可写作 `![视频说明](https://example.com/video.mp4)`，支持 `.mp4`、`.webm`、`.ogv`，也可使用 `<video controls src="https://example.com/video.mp4"></video>`。媒体由浏览器加载 HTTPS 直链，视频能否播放取决于浏览器支持的编码；暂不提供文件上传或 iframe 视频嵌入。脚本、事件属性及危险链接会被过滤。

购买者在下单弹窗填写领取密钥，右侧“生成”使用安全随机数生成固定 24 位小写英文和数字混合密钥，“复制”用于保存。自定义密钥不要求字符组合，允许中文、符号，区分大小写及前后空格，须为 1–128 个字符且不能全部为空白。一笔订单对应一个密钥，关闭、过期或后台删除后仍不可复用；重复时提供三个派生候选供点击回填，最终以下单时服务端校验为准。密钥是查询及领取的唯一凭证，简单密钥容易被猜中，建议使用自动生成；丢失后无法自动找回。

点击“前往支付”后，弹窗内等待 HashPay 返回支付链接并直接跳转，不再经过本站订单中转页。暂未取得链接时保留密钥、数量和请求标识，可以继续获取；网络中断、刷新或重新打开同一商品的弹窗后重试会复用原订单及预留库存，并展示原订单金额。支付完成后返回 `/claim`，同一浏览器会话可恢复当前订单；顶栏“查询 / 领取”也可打开此页，在其他设备只输入密钥即可查看订单、继续支付或复制已交付商品。浏览器存储不可用时，须先成功复制密钥，或勾选已手动保存，才可前往支付；付款后输入密钥查询。

领取密钥仅通过本站 JSON 请求体传输，不进入 URL，不发送给 HashPay，服务端只保存 SHA-256 哈希。查询失败按 IP 限流，连续 10 次失败后等待一分钟再试。

后台订单详情提供刷新状态、删除订单和重试交付。付款状态由 HashPay 签名查询结果决定，店主不能在本站手动改为已付款或关闭。网关 `expired` 不代表永不付款，因此继续保留库存；核验为 `invalid` 后自动释放尚未交付的库存。若原网关、原商户查询明确返回 `404` 和原生错误码 `errors.order_not_found`，未付款订单会自动关闭、释放预留库存并停止补查；已核验付款的订单保留付款和领取结果，未完成交付继续执行。普通 404、网关或商户配置不符、尚未核验归属的订单不会触发释放；订单在完整查询核验后记录网关归属。本站后台删除只从列表及统计中移除订单，保留网关映射、补查任务和购买者领取结果，不取消网关订单。

后台“优惠管理”维护自动活动与优惠码：适用全店或指定一个/多个商品，可设置起止时间、最低原价合计、最低数量、总使用次数及启用状态；不填时间即常驻，总次数为 0 表示不限。减免比例填 20 表示八折，固定减免按每单计算，固定减免和金额门槛须指定币种，比例优惠可跨币种。优惠码不区分大小写，可手工填写、随机生成并复制派发。匿名购买不提供按用户限次。

买家在下单弹窗输入优惠码，服务端选择最多一个活动和一个优惠码的最优惠组合；只有双方都开启“允许与其他优惠一同使用”才先活动后优惠码，否则取更优惠的单项。每项减免向下取整，实付至少保留一个最小货币单位。预览不占次数，下单与库存预留在同一事务中占用；待付款、过期或已付款订单均保留次数，未付款订单可靠关闭/失效后才归还，已核验付款的次数不退回。删除后台订单不归还次数。下单时重新核验报价金额与币种，变化后需重新确认；订单保留优惠快照，修改或删除活动不改变历史金额，HashPay 核验始终使用订单实付金额。

Markdown 详情支持 `markdown-it-container` 的 `:::` 容器。`tip` / `success`、`info` / `note`、`warning`、`danger` / `error` 分别显示提示样式，`details` / `spoiler` 显示可点击展开的折叠内容；`tabs` 内的 `tab-item` 显示为可点击切换的标签分页，默认选中第一项，窄屏下标签栏可横向滚动；其他小写英文名称显示普通容器。标题可选，容器内支持 Markdown、图片和视频。嵌套时，外层使用更多冒号，例如 `:::: warning` 配合内层 `::: tip`；代码块内的 `:::` 保持为代码，`ansi` 仍作为普通代码块展示。

```markdown
::: warning 购买须知
请先确认商品适合你的用途。
:::

::: details 更多说明
这里可以填写列表、图片或视频。
:::

:::: tabs
::: tab-item 💻基本信息
这里填写基本信息。
:::
::: tab-item 🎬IP质量
这里填写 IP 质量报告。
:::
::::
```

赞赏页地址为 `/donate`，默认关闭。后台侧边栏“赞赏页”（`/admin/donation`）可配置启用状态、标题、Markdown 说明、币种、最多 8 个预设金额及自定义金额上下限，也可复制公开页面链接、查看赞赏记录和刷新付款状态。每次配置一个币种，金额按该币种的常规单位填写；预设金额用逗号分隔，留空时仅提供自定义金额。启用前须在系统设置中完成 HashPay 配置。

赞赏创建后进入 `/donate/orders/:id`，先保存完整私密查询链接，再前往 HashPay。付款回跳通过当前浏览器会话恢复凭证，浏览器无法存储时须先手动保存链接。赞赏独立记录，不创建商品订单、不消耗库存、不参与优惠或商城订单统计。付款须经服务端查询核验商户、订单号、金额及币种；重复通知不重复计入统计，过期记录继续补查可能迟到的付款。停用页面只停止新的赞赏，历史查询与付款补查继续保留；存在待核验赞赏时不能更换支付网关或商户，已核验收款按币种分别汇总。

## 🧠 功能细节

核心表包括 `products`、`inventories`、`stock_items`、`orders`、`deliveries`、`admin_sessions`：商品通过 `inventory_id` 关联库存池，库存项属于库存池；订单另存下单时的库存来源和交付快照。优惠使用 `promotions`、`promotion_products`、`order_promotions` 保存规则、适用范围及订单占用关系。数据库启用 WAL、外键、busy timeout 和单连接事务。金额按币种精度以整数保存，JSON 金额按十进制解析核对。支持 CNY、USD、EUR、GBP、HKD、JPY、USDT 和 USDC。

库存、固定内容和交付结果使用 AES-256-GCM 加密，并通过记录 ID 的附加认证数据防跨记录替换。去重密钥独立保留；领取 Token 和管理员会话只保存 SHA-256 哈希。配置文件与商户私钥不由静态服务提供，不在 API 返回。

HashPay 创建超时重试复用 `merchantNo`。回调解密成功不能证明来源，付款确认必须签名查询并匹配商户、订单号、金额、币种和 `paid`；HashPay 自动确认及管理员确认均按网关状态接受。首次启动在事务中创建完整 SQLite 结构，启用外键约束，后续启动保留订单、库存与交付记录。

## 🧱 技术栈

- 后端：Go、`net/http`、modernc SQLite、`x/crypto` Argon2id。
- 前端：Vue 3、TypeScript、Vue Router、Naive UI、Vite、SCSS；markdown-it 与 markdown-it-container 解析详情，DOMPurify 清理展示内容。
- 运行：Go `embed` 静态资源、SQLite、Docker Compose；也可使用 systemd 部署二进制。
- 验证：Go 集成测试、Playwright 真实浏览器与测试 HashPay 边界。

## 👨‍💻 本地开发

### 🧰 环境

Go 1.27+ 和 Node.js 24+。Windows 本地服务只监听回环地址。Windows 使用 ACL 限制配置及私钥访问；POSIX 系统强制配置和私钥 `0600`。

安装前端依赖后启动后端，配置尚不存在时自动进入网页初始化：

```sh
npm --prefix frontend ci
go run ./backend
```

在另一终端运行 `npm --prefix frontend run dev`，访问 `http://127.0.0.1:5173`，在初始化页填写管理员账号和密码。站点地址保留为 Vite 的实际访问地址；它用于登录和 CSRF 的 Origin 校验。HTTP 使用 HttpOnly、SameSite Cookie，HTTPS 地址额外启用 Secure。测试网关仅存在于 Go 测试代码中，生产程序没有模拟付款接口。

### ⚙️ 命令

```sh
go test ./...
go vet ./...
npm --prefix frontend run check
npm --prefix frontend run build
cd frontend
npx playwright install chromium
npm run test:e2e
```

后端测试按初始化、数据库、商品、库存、支付、密钥领取、优惠和赞赏归类，验证当前结构与业务边界；浏览器测试按初始化、购买、密钥领取、商品、库存、优惠、赞赏和语言归类，共用登录、库存准备及页面错误检查。浏览器测试运行临时 SQLite、临时 RSA 私钥、回环后端与 TLS 测试网关，覆盖购买领取、保存后重新读取、库存共享与改绑、报价确认、赞赏付款和代表性视口。测试不接触真实商户或真实付款。已有 Chromium 时可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定路径。
